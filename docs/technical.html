How the measurement becomes a lending price.

Herkos keeps the lending integration familiar while making exit capacity part of the price signal.

Measurement model

Capacity falls as exit size grows

The oracle starts with a reference FXRP price from the existing feed. It measures the time and capacity needed to settle an exit, then derives a haircut for the requested size. The haircut is bounded and cannot improve the price because of missing or optimistic evidence.

The key inputs are the open redemption queue, liquid Core Vault funds, and only the trading pools that can convert FXRP into a stable asset without counting correlated XRP rotations as new exit capacity.

effective lending price = reference price × measured haircut

Data sources

Each source has a defined job

Flare contracts

Reads public contract state for queue depth, supply, vault accounting, and market exposure at one block.

XRP Ledger

Checks the Core Vault account and condition-gated escrow records against the source ledger.

Flare Data Connector

Supplies finalized cross-chain evidence. The proof path only subtracts capacity when the evidence is accepted.

Eligible markets

Uses uncorrelated exit depth. A pool that only moves value inside the XRP ecosystem is excluded from the conservative capacity number.

Contract interface

Designed for existing lending markets

The contract exposes getUnderlyingPrice(address), the same method used by Compound-style price oracles. Non-FXRP markets delegate to the incumbent oracle. FXRP reads use the measured haircut for the configured reference size.

Governance controls configuration and venue registration. Price and haircut are derived from measured state rather than submitted by an operator.

Refreshing the measurement is permissionless, but production still needs a clear update cadence and an incentive for the caller.

Verification

What the public result proves

The pinned result is traced to the repository run files and a shared fork block. The public page shows the block, capture time, proof reference, and explorer link. It does not compare a live market price with a recorded Herkos price.

  • Foundry tests cover the hot path, venue handling, proof path, guards, and refresh behavior.
  • The presentation check traces displayed figures to the files that produced them.
  • The browser demo is read-only. It does not request a wallet or send a transaction.
